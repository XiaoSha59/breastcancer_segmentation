BACKEND INTEGRATION — COPY + RUN
================================

1. COPY FILES
-------------

Copy the folders/files from this pack into the ROOT of MRI-Project,
preserving the paths.

NEW:
  reproducibility_backend/
    __init__.py
    app.py
    requirements.txt
    README.md
    .env.example

  reproducibility/run_live_audit.py

  reproducibility_site/src/api.ts
  reproducibility_site/src/backend.css

REPLACE:
  reproducibility_site/src/App.tsx

APPEND:
  contents of GITIGNORE_ADDITIONS.txt -> root .gitignore


2. INSTALL BACKEND
------------------

Open Terminal #1 in MRI-Project.

macOS / Linux:

  python3 -m venv .venv
  source .venv/bin/activate
  python -m pip install -r reproducibility_backend/requirements.txt

Windows PowerShell:

  py -m venv .venv
  .\.venv\Scripts\Activate.ps1
  python -m pip install -r reproducibility_backend/requirements.txt


3. TEST THE REAL AUDIT WITHOUT THE WEBSITE FIRST
-------------------------------------------------

Still from MRI-Project root:

  python reproducibility/run_live_audit.py

It should finish with PASS messages and exit normally.

This is important: if it fails here, fix the underlying reproducibility
check before testing the browser UI.


4. START THE BACKEND
--------------------

Terminal #1, from MRI-Project root, with the venv active:

  python -m uvicorn reproducibility_backend.app:app --host 127.0.0.1 --port 8768 --reload

Expected:

  Uvicorn running on http://127.0.0.1:8768

Optional browser check:

  http://127.0.0.1:8768/api/health

You should see JSON with:

  "ok": true


5. START THE FRONTEND
---------------------

Open Terminal #2.

  cd MRI-Project/reproducibility_site
  npm install
  npm run dev

Open the Vite URL, normally:

  http://localhost:5173/

The header should show:

  Python backend online

Click:

  Run real audit

Now the browser starts the actual Python audit through FastAPI and streams
the real stdout back to the log panel. The characters are revealed with a
small cosmetic typing animation, but the text itself comes from the real
backend process.


6. STOP
-------

Frontend terminal:
  Ctrl + C

Backend terminal:
  Ctrl + C


7. PRODUCTION-STYLE LOCAL DEMO (ONE SERVER)
-------------------------------------------

Build the frontend:

  cd MRI-Project/reproducibility_site
  npm run build
  cd ..

Start backend without --reload:

  python -m uvicorn reproducibility_backend.app:app --host 127.0.0.1 --port 8768

Now open:

  http://127.0.0.1:8768/

FastAPI will serve the compiled frontend and the /api routes from the same
local server.


8. WHAT TO COMMIT
-----------------

Do commit:
  reproducibility_backend/
  reproducibility/run_live_audit.py
  reproducibility_site/src/App.tsx
  reproducibility_site/src/api.ts
  reproducibility_site/src/backend.css
  reproducibility_site/package-lock.json   (if npm created/updated it)
  root .gitignore changes

Do NOT commit:
  .venv/
  reproducibility_site/node_modules/
  reproducibility_site/dist/
  .env files
  reproducibility/_generated/


9. IMPORTANT BEFORE PUBLIC DEPLOYMENT
-------------------------------------

For now the backend binds to 127.0.0.1 and is meant for your local demo.

Do NOT expose the live execution API directly to the public internet yet.
Before a public deployment, add authentication/rate limiting or use a
read-only/static replay mode. The backend deliberately runs only one fixed,
whitelisted audit script and accepts no arbitrary shell command from the
browser.
